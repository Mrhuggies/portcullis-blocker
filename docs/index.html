Why one blocker isn't enough

Every blocker has a hole. A browser extension is removed with two clicks. A DNS filter is switched off in settings. A hosts file is edited by anyone who can type sudo. On its own, each one stops you for about forty seconds.

Layering changes the arithmetic. To get through, you have to defeat all of them, each needing a different trick, while a part of you is already arguing that this is stupid and you should stop. That argument is the thing we're buying time against — most urges fade within about twenty minutes if you don't act on them.

The honest version: none of this is unbreakable, and anyone who tells you their blocker is unbreakable is selling something. You own the machine; with enough determination you will get through. The point is that every route takes several deliberate steps and a wait, and urges don't survive that.

Install it

Step-by-step guide with screenshots → every screen you'll see, for Mac, Windows, Android and iPhone.

Start with the computer you use most. Each part works on its own, so you can stop after one layer and still be better off than before.

macOS

The easy way: download Portcullis for Mac, unzip it, drag Portcullis into Applications and open it. The first time, macOS will refuse because it isn't from the App Store: go to System Settings → Privacy & Security, scroll down and click Open Anyway. Then press Turn on. The app installs the block list and watchdog, and lets you add your own sites and block bypass tools like Tor. The steps below do the same thing by hand.

  1. Download the project and unzip it, then open Terminal in that folder.
  2. Block it everywhere:
    sudo bash mac/install-hosts.sh
    Covers Safari, Chrome, Firefox and every app. Asks for your Mac password — nothing appears while you type it, which is normal.
  3. Lock Chrome's settings: double-click mac/Portcullis.mobileconfig, then approve it in System Settings → General → Device Management.
  4. Turn on the watchdog so the block repairs itself: 
    sudo bash mac/install-guard.sh
  5. Check it: sudo bash mac/test-guard.sh removes the block and shows you it coming back. If the watchdog fails, the test puts it back itself.

Windows

Status: the file handling is covered by automated tests, and every script is checked by Microsoft's own PowerShell parser; the app's rules and its security checks are tested the same way as the Mac version's. The Windows-only parts — the permission prompt, registry policy and the scheduled task — have not yet been run on a real Windows machine. Your hosts file is backed up before anything is written, and uninstall.ps1 restores it.

The easy way: download Portcullis for Windows, unzip it somewhere permanent such as Documents, and double-click Portcullis.cmd. If Windows says it protected your PC, choose More info → Run anyway. Press Turn on and say yes to the permission prompt. The app sets up the block list, the watchdog and the Chrome/Edge lock in one go, and lets you add your own sites. Or by hand:

  1. Download the project and unzip it, then open PowerShell as Administrator in that folder.
  2. Block it everywhere:
    powershell -ExecutionPolicy Bypass -File .\windows\install.ps1
    Writes the hosts file and locks Chrome and Edge policy, including turning off the browsers' own secure DNS so they can't resolve around the block.
  3. Turn on the watchdog:
    powershell -ExecutionPolicy Bypass -File .\windows\install-guard.ps1
    Registers a task that checks every five minutes and repairs the block.
  4. Restart Chrome and Edge completely and try a blocked site.

Phone — both platforms

DNS filtering covers every app on the phone, on wi-fi and on mobile data. It's free.

  1. Make your own NextDNS account at nextdns.io. Free covers 300,000 lookups a month, which is plenty for one phone. Use your own account — never someone else's ID, or your browsing is recorded in their dashboard.
  2. Parental Control → Categories → add Porn. Not the Privacy tab; that's only ads and trackers. Add any sites you personally want gone under Websites, Apps & Games.
  3. Settings → Logs: turn logging off or set the shortest retention, unless you want the record.
  4. Android: Settings → Network & internet → Private DNS → enter yourid.dns.nextdns.io.
    iPhone: go to apple.nextdns.io in Safari, pick your profile, tap Download, then Settings → Profile Downloaded → Install.

AppBlock — the strongest phone layer

DNS filtering stops sites. It can't stop an app. AppBlock adds that, and its Strict Mode is the part that matters: once on, you can't edit your blocks, pause them, or uninstall the app until you satisfy whatever unlock you chose — a PIN, plugging in a charger, a timer, or a cooldown.

Android

Uses device-admin permission to prevent uninstall, and can block access to device settings. This is the stronger of the two implementations.

iPhone

Has "Disable App Uninstalling", but some users report it being bypassed via Screen Time. Treat it as friction, not a lock.

Set the unlock to a cooldown of several minutes rather than a PIN you know. A PIN you can remember is not an obstacle at 1am.

Is it safe? What is it actually doing?

Fair question, and you shouldn't take anyone's word for it — including mine. Here's exactly what it touches and how to check.

No account. No sign-up. No telemetry. Nothing is sent anywhere. The scripts are plain text you can read in a few minutes. The only network request in the whole project downloads a public blocklist from GitHub.
What it changesWhyHow to check
Your hosts filePoints blocked domains at nothing It's a text file. Everything is between two marker comments; your own entries are left alone and backed up first.
Chrome/Edge policyBlocks the top 1,000 sites, turns off browser DNS Open chrome://policy and read every value it has set.
A background taskPuts the block back if it's removed One small script, guard.sh or guard.ps1. It writes a log of everything it does.

What it does not do

  • No record of what you browse. It can't see your browsing; it only knows a blocked name was asked for.
  • Nothing is uploaded, and there is no server. It keeps working with the wi-fi off.
  • No hidden master password or backdoor. The removal path is documented below, and it's the only one.

The one real privacy trade-off

If you use the DNS layer, NextDNS sees the domains your devices look up. That is how filtering works — something has to answer the question. They're a paid-subscription business rather than an ad one, logging is optional and you choose the retention, but it is a genuine trade and you should make it knowingly. Skip that layer if you'd rather not; the rest still works.

How to remove it

Documented on purpose. A tool that hides its own exit isn't trustworthy, and you'll legitimately need this one day — a new laptop, a work machine, a changed mind.

macOS:    sudo bash mac/uninstall-hosts.sh     # files the request
          sudo bash mac/uninstall-hosts.sh     # again after 48 hours
Windows:  powershell -ExecutionPolicy Bypass -File .\windows\uninstall.ps1       # same two steps
          powershell -ExecutionPolicy Bypass -File .\app\windows\uninstall.ps1   # (from the app's folder)

The first run doesn't remove anything — it starts a 48-hour clock and tells you when you can come back. --cancel (or -Cancel) calls it off. Browser policy is removed separately in System Settings or the registry, and the phone layers come off in their own apps.

If a site you need is blocked by mistake, don't remove everything — sudo bash mac/allow-site.sh example.com unblocks exactly one. Instantly for ordinary false positives; after an hour for anything on the adult list.

What it can't reach

  • Other devices — a tablet, a work laptop, a console. Each needs its own setup.
  • VPNs — a VPN app doesn't defeat the hosts file, but it does defeat DNS filtering.
  • Content inside big platforms — Reddit, X and Telegram serve it from the same address as everything else. Blocking the whole site is the only lever.
  • You, if you're determined enough. It's your computer and your password. This buys you twenty minutes and a cooling-off period, not impossibility.
The layer that actually changes the ceiling isn't software. It's another person: someone who holds the Screen Time passcode, or just someone who knows you're doing this and asks how it's going. Every technical layer here is friction. A person is accountability.

Portcullis is free and open source. Read the code before you run it — all of it is plain text, and that's rather the point.
